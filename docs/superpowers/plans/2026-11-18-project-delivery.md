# 鲸言鲸语完整交付实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Each workstream below is a delivery package, not one PR. Before implementation, split the next dependency-ready package into focused tasks with exact files, interface and a failing acceptance case; do not start every package at once.

**Goal:** 从可联调的主干推进到可在干净 Windows 宿主部署、Android/Windows 双端可用，并有 AC-01～35 和 CR-01～12 证据的完整自托管小圈子产品。

**Architecture:** 不换框架或重写已合入路径。宿主负责权限、持久化和业务状态，Flutter 负责可操作流程和本地状态；模块间复用现有契约，跨模块变更先明确调用方和升级影响。按依赖组织内部里程碑，最终仍按规格一次完整交付。

**Tech Stack:** Dart/Flutter、SQLite、Windows 宿主与 Android/Windows 客户端、受控 HTTP worker、LAN/tailnet。

**Spec:** [规格 v4.2](../../../鲸言鲸语-需求规格-v4.2.md) §§3–20、[需求口径](../../architecture/02-decisions.md)、[模块依赖](../../modules/README.md)。证据以[验收记录](../../acceptance.md)、[需求追踪](../../requirements-traceability.md)、相应 PR 与实际复验为准。旧文档的「待写」或「未合并」是该文档历史基线，不直接算当前缺口；形象以 v4.2 FR-38/39 的后续口径为准。

## Global Constraints

- Android + Windows；不新增 Web、公开注册或公网宿主范围。权限、消息规范、部署拓扑以现有规格为准。受保护出站沿用现有 URL/DNS/TLS 校验，审计无正文、音频和密钥。
- 暂无可用目标设备时可用模拟环境开发和做预检，但不替代安卓实测。NFR-04：街区位置同步 2–5Hz、客户端插值；同屏 ≤8；中端安卓室内 30fps、骁龙 888 稳定 30–60fps 为目标，记录设备、分辨率、场景、帧率和显存，不报理论通过。
- 默认不启用主动 AI；未授权来源和敏感正文不进入模型、日志、导出；未知使用量不写成零。按已定优先级处理记忆，禁止采集优先；人格或内容权限冲突先登记，不用 fixture 给生产放行。
- Live2D 每端独立、模型和映射只保存在本机，不随安装包、附件或共享备份分发。个人使用上传不作事前授权校验；运行时发行边界仍需按 FR-38/39 与 NFR-12 核对。
- 普通 PR 基于 `main`，不自合、不强行通过检查。涉及 UI 用真实同场景、同视口、同主题和状态的 Before/After，标注修订；合成数据可用，截图不能代替真机。缺证据保留草稿。

## 2. 里程碑与依赖

时间从确认本表后**相对**计算。首轮 1–2 个工作日目标是拿出一条可验收的核心用户路径，不是完整项目 ETA。后续每轮 2–3 个工作日复核剩余量、依赖和设备可用性；不在薄弱证据上承诺发布日期。R1～R4 是内部验收门，不是砍掉功能分批发布。

| 门槛 | 主线上要交付什么 | 可同时做的独立件 | 出口证据 |
|---|---|---|---|
| R1 核心会话可用 | 完成本人 AI 私聊入口；同一客户端实跑登录/配置/同意→发送→真实回复显示→重连读回；接着打通好友请求→处理→私聊/群聊的阻断点。 | 收件箱手动刷新；备份文件保存/选择；复用原生通知/分享接线；Live2D 完成安全导入及渲染准备。 | 合成测试数据和真实 `auto`，按实际启动流程测试；旧 session、撤权、离线不误发，canonical ID 只有一条。 |
| R2 可靠双端与数据可带走 | 接设备会话/未读/同步和消息操作；附件在聊天内真能选、发、看；系统通知与分享、选文件导入导出、干净宿主恢复。 | 做明确的模型能力入口和预算诊断、语音消息/TTS/ASR、Live2D 首帧及 VRM 回退；记忆/提议权限契约可在隔离环境开发。 | Windows/Android 可复跑脚本与设备矩阵；坏包不写、无明文 key/T2、测试恢复 `integrity_check` 有结果。 |
| R3 产品全功能闭环 | 权限和状态完成后，逐步接记忆/生活/创作、社交、世界、通话。所有只读页对应的在范围功能要有生产入口和结果。 | 已冻结接口的子模块可并行；场景跨端合测，边做边补 AC 缺证据。 | CR 子项、权限/静默窗、真实厂商、导航/热切换、回滚及功能级验收。 |
| R4 发布候选 | 同一候选修订从零部署、双端日常使用、加密恢复演练、发布前隐私及泄漏复核。 | 两平台设备测试、压力与失败恢复、各域串数据检查分给不同执行者。 | 全部 AC/CR、发布阻断问题清零、安装/部署/回退可复现；未完成不得称完整落地。 |

**关键路径**：已有宿主与客户端基础 → 本人 AI 入口及实际联调 → 双端会话可靠性与账号隔离 → 集成验收。**独立的长路径**：本机形象导入→可渲染→热切换/回退→真机；语音权限→TTS/ASR→通话/语音房；生命周期文件→密文备份/恢复→账号离开。每条都尽早消除前置，最后在 R4 汇合。

## 5. 发布门槛与复核频率

每个内部门只看实际可验收能力：编译/测试/CI 通过，正反权限边界、合并的准确修订、可复跑的真实证据。项目级检查执行仓库 `tool/check.ps1` 和 Flutter 完整套件；设备相关另测 Windows 实际安装/通知路径和授权 Android 真机。最终用干净宿主 + 两设备从新账号走一遍完整流程，核对 AC-01～35（AC-27 含全部 CR）、NFR-05/06/07/09/11/12、从零部署和恢复。测试跳过不算通过；未配置真实厂商、未接设备、未验证授权或没有恢复证据的相应项保持开放。

每次内部里程碑同步三件事：已通过的 AC 与证据、下一条关键路径及负责人、仅需要人员解决的阻塞。常规工作由组内继续，不按 PR 数量上报百分比。若两轮后关键路径仍不前进，先重新排序依赖和缩小并发，而不是加页面或套件重复验证。计划获确认后，各组按就绪条件领第一个交付片；未获确认的新增产品判断不落代码，继续已授权在途实现。
