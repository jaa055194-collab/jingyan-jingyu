## 需要协调的具体接口

1. **账户存储**：新`AccountsStore.serialized`暴露全量内存state并保证单isolate串行，不是SQLite transaction。M01的`Database.transaction`是SQL事务，不能通过序列化整个state冒充持久化存储。需要把账户/邀请/设备操作明确为数据库内原子操作，保留对应的内存实现和契约测试，迁移使用100–199。
2. **宿主鉴权**：现有`Host.auth`公开类型为`StaticTokenAuthenticator`，既有调用者调用`issue/revoke`。直接改为数据库鉴权会改变调用者预期。需要明确开发测试token适配入口与正式`Authenticator`装配，不能悄悄让生产回落静态token。
3. **迁移装配**：M01持有统一迁移表，M02应在单次数据库启动中加入100–199迁移；不能另开连接或修改已发布迁移。
4. **可信请求元数据**：HTTP适配器尚未传递经过信任边界验证的客户端IP/设备信任标记。限流和宿主设备身份不能信任请求body、自报header或管理员身份。M11的`isHostMachine`需要来源于经认证设备信任状态。
5. **邀请码管理**：规范`issue`仅返回code而`revoke`需要inviteId，当前领域接口不提供签发元数据或管理列表。需要在管理员管理接口中提供可撤销的元数据；不可对普通用户暴露邀请码hash。
6. **插件新增能力**：规范要求readConversation/modelInvoke，当前上下文尚无这些注入接口。需在保证可见性、敏感内容不送模型、模型预算计量的前提下接入，不能凭UI按钮绕过宿主验证。

这些是账户持久化、宿主装配、协议/HTTP边界和客户端多个独立模块的协调点。本分支保留可验证局部成果，不用空壳接口宣称它们已经完成。用户已允许必要的常规接入改动；是否就绪仍以实现与验证证据为准。
