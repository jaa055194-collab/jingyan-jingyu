# 实现状态与接续边界

当前主干基线：`0626ae3`，包含已合并 M01（PR #6）及 M02（PR #9）。本分支按用户授权继续实现；这是完整交付中的增量，不能当作全产品已完成。

## 已合并前置

M01 提供 SQLite、事务迁移、Windows 密钥保护、加密列及持久审计。M02 提供持久账号/邀请/设备、生产鉴权、HTTP、初始化与限流。沿用主干实现，不保留第二套账号 schema 或鉴权；早期本票账号原型已移出工作树，避免与主干冲突。

## 本分支增量

- 插件激活期复用受限上下文，保持私有内存状态；能力不可变快照，失败激活/停用后上下文失效。公开签名不变，不承诺跨重启保存。
- M12 配额与并发许可纯策略，边界测试覆盖；未接入真实上传、清理或备份。
- Migration 200 与 `SqliteMessageStore`：正文 AES-GCM（AAD含消息id）、事务 seq/幂等、分页、设备ack、重启持久化。MessageStore仍是内部可信仓储，权限由服务器成员策略执行。
- Migration 300 与群成员权限：创建群、列出本人群、owner添加已存在且有效账号；默认历史all，可创建joined历史群。同一事务记录成员及当时消息head+1；服务器同步强制历史下界。
- 默认宿主装配上述持久消息/成员服务，缺少成员策略时拒绝消息读取和发送，不再默认放行。提供认证群创建、列表及成员添加路由；身份只取principal。
- `StorageModule`增加可选迁移列表参数，默认保持M01原样；默认宿主统一应用1/100/200/300，M02自身启动检测已存在迁移不重复执行。

## 验证

局部31项持久消息/成员/路由/历史/迁移测试已通过。独立审查未发现本增量的严重问题，确认同Tx历史边界、服务器过滤及M02差异行持久化不会覆盖消息/社交数据。默认宿主端到端和最终全仓证据在PR描述及需求追踪中更新；旧版本的测试结果不代表后续提交通过。

## M05 当前前置（未完成模型调用）

新增按认证账号隔离的provider CRUD与加密key存储（Migration500），默认宿主已挂配置路由；返回仅掩码视图，审计只记录动作/目标。Migration501显式建立AiId档案到AI账号的映射，不能直接混用两种ID。单次非流式OpenAI-compatible适配器已局部验证严格usage、安全错误和不重试。

Guarded HTTP原型每次解析并固定已校验IP，真实TLS显式使用原域名验证，无证书绕过，不跟3xx。独立审查发现并修复初版自定义socket跳过TLS的严重缺陷，真实TLS正反例已验证。仍有明确Important：停滞TLS握手超时后无法立即强制关闭底层连接；仅以每isolate共享8个握手名额将资源有界，满额失败关闭。恶意端可耗尽这些名额。因此transport/adapter不接入生产模型调用，不能宣称M05可用或把此隔离措施说成清理已解决。

尚无binding/用户预算与时区配置、usage计量硬停、chat.fast路由、模型发现/连接测试、生图或真实AI回复链。前置48项（provider7/HTTP6/identity11/transport13/adapter10/默认装配1）局部验证通过，最终全仓证据另记。
