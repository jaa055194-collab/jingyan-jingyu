# 公开前隐私检查与占位符

## 占位符约定

| 占位符 | 含义 | 使用范围 |
|---|---|---|
| `PRIVATE_AI_PERSONA_1` | 历史材料中的同一个私人 AI 人设名称 | 历史需求、设计取舍记录、当前规格的历史依据 |

同一个原值始终使用同一个占位符。本文只记录类别，不记录原值、可反推原值的摘要或私有来源链接。逆向映射仅保存在仓库外的私有记录中，不得放入 PR、Issue、提交信息或发布附件，也不要复制到工作副本内。`.privacy-local/` 的忽略规则只是防止意外暂存，不是建议在仓库内保存映射。

## 检查边界

本次文档替换仅去掉名称，不改变需求、权限边界、SDK 许可要求或运行行为。代码中的示例域名、环回地址、SSRF 拒绝测试所用私网地址，以及明确的测试凭据/测试 TLS 密钥属于测试数据，不应当作真实部署信息删除。第三方开源项目的公开来源和许可署名应保留。

**当前文件脱敏不等于可以直接公开整个仓库。** 普通 PR 不会擦除历史提交、其他分支、提交作者邮箱、PR/Issue 及评论、工作流日志/制品或发布附件中的旧值。切换可见性前，仓库所有者仍须检查这些可公开表面；如发现真实凭据，先吊销或轮换，再清理留存副本。涉及共享历史重写、协作者归属或讨论记录删除时，应单独确定保留与清理方案，不能靠这份文档或新增提交声称历史已清除。

本地 `.env`、`.env.*`、`secrets.local/` 和 `.privacy-local/` 已被忽略，但忽略规则不会移除已跟踪文件，也不能替代提交前检查。允许提交的 `.env.example` / `.env.*.example` 也只能含无效示例值。
