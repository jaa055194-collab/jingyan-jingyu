# Android 优先：消息表情回应客户端

基线 `fda8453735016b88f4a89040d62ee09a5c3169e9`；客户端代码 `3b4378b2fc0e3c2e246a7c5e75d7c7347d39a10e`。需配套任务 16 的宿主边界校验 `096f8c541e7f8712c8d07605a44a5696e0c19371`；客户端过滤不能代替旧宿主欠缺的可见性校验。既有 GET/POST 路由、JSON 和许可语义未改动。

- 仅当前已同步、可见、未撤回的消息：`⋯ → 表情回应` 后才读取列表；打开聊天或原菜单不做读取。六个固定表情（👍 ❤️ 😂 😮 😢 🙌），展示聚合计数与本人是否已回应。不展示、存储或转发原始账户标识和不在固定选择中的旧回应；不会给旧字符串归一化，也不增加服务端白名单。
- 直接点击添加，再点已选表情取消。每次仅单个 POST；同一按钮旧回调或写入进行中不会重复触发，禁止写入期间以返回键、外部点击、滑动或关闭按钮退出面板；会话状态变化仍使回应视图失效。仅在严格的成功回执（同一 emoji 与 bool active）和随后一个 GET 的本账号状态一致时显示「已确认」。多设备并发使回执与读回不符时不显示成功。
- 结果未知、拒绝、空列表、不可读取、离线不是同一状态。未知/拒绝不自动重试或自动 GET；显式「刷新」只读当前状态，失败重读保留未知提示。切换账号/聊天/锁定或消息不再可用会屏蔽晚回执；已发出的请求可能在宿主生效。
- 离线/忙碌不写。无轮询、推送、缓存落盘、同步或 ACK 游标改动；不会自行显示到气泡或其他设备，须打开回应面板查看。屏幕尺寸优先适配手机，不改相邻置顶、复制、编辑、撤回、收藏和附件的交互合同。
