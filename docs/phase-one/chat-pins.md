# 聊天置顶：会话内查看、置顶与取消

从 `1a04fad5a8745432587716772e95898f00f0c6e0`（与已合并 #175 后的 `80828d8` 同源树）开始。客户端代码修订 `11c619394dcb61cf26fe4bc9d029458e5241470e`；客户端不改 `shell_app`、协议、差集同步、原生平台或账号存储。应与本次宿主置顶鉴权补强配套使用，不能用旧宿主或客户端过滤代替服务端权限。

## 用户流程与边界

- 在当前会话点标题栏「置顶消息」，只显示本端已同步、当前仍可见且未撤回的置顶消息。客户端不展示服务器返回的置顶人 ID、时间、未知或删除的消息 ID，不为置顶回补历史，也不动 ACK/未读游标。有效空列表表示“当前可见的消息中没有置顶”，不承诺会话所有历史已下载。
- 在可见已发消息的 `⋯ → 管理置顶`，先读出当前状态，再明确点「置顶」或「取消置顶」。这是对整个会话的变更，不是个人收藏。客户端只把当前会话的有效消息当作候选，宿主判定读写权限；不是“原作者或置顶人才能更改”。不改复制、编辑、撤回、收藏入口。
- 成功只读准确回执；回执正确时重读列表，重读失败显示不可用，不猜测空或显示乐观结果。宿主拒绝和结果未确认分别提示；写请求不重放或自动重试。未知结果只能通过明确「刷新」确认当前状态，失败的刷新不会清除不确定提示。离线不发请求，重连后可明确刷新。
- 会话、登录或锁定状态变化以后，旧确认不能发写请求；晚到的读取或回执不显示在其他会话。切换后已经发到宿主的请求不承诺取消。未加入推送、多客户端实时同步、设置、排序重设计、附件下载或新消息功能。

## 宿主授权与审计

- 列表以当前会话的历史起点为界，排除已撤回或已不存在的消息。置顶和取消在同一事务内同时核对消息可见性和会话发帖权限；无法查看的消息与不存在的消息返回同样的 404。仍可读取历史的已拉黑私聊不得置顶或取消。
- 每个会话最多 50 条有效置顶；撤回或删除的旧条目不占名额。重复置顶、重复取消不会改变结果，也不重复留痕。实际改动与 `message.pin` / `message.unpin` 审计同一事务提交；审计仅记录操作者、目标消息和会话 ID，不含正文。
