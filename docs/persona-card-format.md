# 人格卡 JSON 格式（第一期）

第一期只支持一种固定格式，用于把一个人格草稿导入客户端 AI 运行配置页。导入**只填充表单**，不会初始化或保存到宿主；用户仍需在现有界面明确点击“初始化人格”或“保存人格修改”。

## 结构

顶层对象必须且只能包含四个字段：

```json
{
  "format": "PRIVATE_AI_PERSONA_1",
  "p0": {"name": "示例名", "role": "示例角色"},
  "p1": {"style": "示例风格"},
  "p2": {"mood": "示例情绪"}
}
```

- `format` 固定为字符串 `PRIVATE_AI_PERSONA_1`。其他值、缺失或额外字段都会被拒绝。
- `p0`、`p1`、`p2` 都是非空对象，每层 1–32 项；键与值都是非空字符串。
- 不支持记忆、音色、形象、版本、权限、模型或任何额外字段；这些不会因导入而创建或修改。
- 示例见 [`examples/persona-sample.json`](examples/persona-sample.json)。

## 限制

| 规则 | 边界 |
| --- | --- |
| 文件/粘贴字节数 | ≤ 64 KiB（64 × 1024 字节，进入 JSON 解析前检查） |
| 编码 | 严格 UTF-8；不接受 BOM、无效字节 |
| 每层条目 | 1–32 |
| 键长度 | ≤ 64 个 Unicode 码点 |
| 值长度 | ≤ 2000 个 Unicode 码点 |
| 字符 | 键和值不能为空，也不能含 C0（U+0000–U+001F）或 C1（U+007F–U+009F）控制字符 |
| JSON | 拒绝重复键、注释、尾随逗号、非对象层、非字符串值、数组和过多嵌套 |

现有编辑器用每行 `key=value` 的文本表单。若某个键含 `=`，或键/值首尾有空白，导入会明确报错而不是悄悄改写内容。

## 两个入口

- **导入人格文件**：只读取用户主动选择的本地文件；校验失败、取消或超限都不改表单，也不保留路径。选择器由既有平台通道提供，临时副本读取后删除，用户自己的文件永不被删除或覆盖。
- **粘贴人格 JSON**：在对话框中粘贴并校验；成功后才填入表单。

两者都会在表单旁显示来源与各层条目数摘要，并注明“仅填充表单，尚未写入宿主”。

## 安全与边界

- 导入流程不调用任何写接口、不发送文件、不访问网络、不记录卡片内容或密钥。
- 导入内容只存在于当前编辑器内存和表单文本中；锁定、登出、账号/AI 切换或离开页面后不会保留导入摘要，切换 AI 时人格三层文本会被清空，避免把 A 的人格误写入 B。
- 此处只校验结构与长度，不代表宿主已接受、已初始化或已启用；最终写入和版本/原因校验仍由现有按钮与宿主负责。
- 该格式不是备份、迁移或插件格式，也不承载任何运行时权限。
